一、本次改动（上一版 0.3.2-3 的真机反馈）
---------------------------------------
真机现象: 卸载 0.3.2-3 后 dpkg 保留 'deinstall ok config-files' 记录；
再次安装时 dpkg 以 `preinst install <旧版本号>` 调用，被 clean-install-only
保护直接拒绝，用户必须先手动 `dpkg --purge` 才能重装。普通用户无法得知这一点，
属于可用性缺陷。

修正: 拒绝条件从"存在旧版本号参数"改为"确实会覆盖已安装的载荷"。
- action == upgrade                → 仍拒绝（原地升级不支持）
- action == install <旧版本号>      → 只读查询 dpkg 状态：
    * 'ok installed'（确已安装）      → 拒绝，提示先卸载
    * 'deinstall ok config-files'     → 放行，按干净安装继续校验
    * 状态不可读                      → 保守回退为检查 root 运行库/服务文件是否存在
查询仅通过 /usr/bin/dpkg-query 只读接口，不做任何写操作；拒绝前唯一的动作就是这次查询。

本次新增的用例:
- 卸载后（config-files）重装不再被保护拒绝，且不要求 purge；
- 覆盖已安装载荷时仍被拒绝，且拒绝前只发生一次只读状态查询；
- upgrade 动作仍在任何操作前拒绝（不读状态、不碰文件、不清理）；
- 状态不可读时回退为按运行库/服务文件存在性保守拒绝；
- prior_state() 对 dpkg 输出的解析与失败回退。

三、附带修正（测试基建，非产品逻辑）
------------------------------------
- 监督器负向对照测试缺少清理函数，导致该用例报错；已补齐 kill_group。
- 该用例会故意制造孤儿进程；现改为在可能失败的断言之前就注册清理，
  避免一次失败运行泄漏孤儿、占用端口、让后续用例连锁超时。
  （本次确曾因此产生一次残留进程并导致后续误报，已定位并排除。）
