一、本版新增 8 个文件接口
--------------------------
jb_list_dir(project, path="", limit=100, offset=0)     列目录，分页；符号链接只报自身元信息
jb_stat(project, path)                                 类型/大小/权限/属主/时间/硬链接数/哈希；链接给出目标
jb_delete(project, path, recursive=false, confirm=false) 删文件或空目录；递归须双确认且不跟随链接
jb_rename(project, src, dst, overwrite=false)          重命名/移动，限同一项目内，默认不覆盖
jb_search(project, root="", name_pattern="", content="", limit=50, ...) 名称通配或内容子串，返回行号与摘录
jb_read_chunk(project, path, offset=0, length=131072)  分块读取，返回整文件哈希与 eof
jb_write_chunk(project, path, offset, data_base64, expected_sha256="", truncate=false, final=false)
                                                       分块写入，支持 CAS 比对，突破 128 KiB 单文件上限
jb_projects()                                          查看已配置项目根（只读；不提供扩大权限范围的接口）

绑定上限（超限报错，不静默截断）：列目录 1..1000、递归删除 ≤10000 项、搜索 ≤1000 条结果/
≤100000 文件/≤16 MiB 单文件/10 秒、分块 1..262144 字节。

安全不变量：全部路径沿用现有 dirfd + O_NOFOLLOW 逐级校验；`.bridge-state` 与 token 对所有
新接口不可达；项目根自身不可删除/重命名；不新增 root 助手，不暴露 token。

二、真机发现并修复的严重缺陷（★）
----------------------------------
现象：`os.listdir(fd)` 在设备 Python 3.9.9 上会**关闭该描述符**（fdopendir 语义），
      而 Python 3.12 不会。三处调用点（列目录、递归删除、搜索）在列举后继续复用同一
      dirfd，在真机上必然抛 EBADF。**启动健康检查只调用两个信息接口，因此会通过检查并被
      提升为正式版本，故障只在用户真正调用新接口时才暴露。**
修复：新增 list_names(fd)，通过 os.dup() 后的副本列举，调用方描述符在 3.9/3.12 上都保持可用。
验证：在设备上用 3.9.9 直接加载暂存版本并调用全部新接口通过（见第四节）。

另修正测试基建两处：
- test_api 的请求体上限用例：更大上限下，服务器回 413 后不排空请求体即关闭，客户端可观测到
  BrokenPipe/ConnectionReset 而非状态码。断言现覆盖这些连接级拒绝（连续 3 次运行稳定），
  并增加“正常体积请求仍会被读取（400）”的对照。
- 新增 4 项“3.9 列举语义”回归测试：把 os.listdir 打桩成 3.9 行为（列举后关闭描述符），
  验证列目录/递归删除/搜索/辅助函数仍然工作。
